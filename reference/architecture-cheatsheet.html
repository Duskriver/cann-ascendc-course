达芬奇 AI Core 硬件模型与流水线速查

以本课典型 Ascend C 向量加法为例查阅数据流；完整架构与优化内容在后续课展开。

🎯 本课的向量加法： 计算接口使用 UB 中的数据，所以先将输入从 GM 搬入 UB，再计算并写回 GM，即搬入 (CopyIn) ➔ 计算 (Compute) ➔ 写回 (CopyOut)。这是一种典型编程范式；不同芯片和接口的能力以对应文档为准。

2. 典型向量加法的三个阶段

典型三阶段流水硬件与核心动作对应关系
阶段 负责硬件单元 对应 Ascend C 核心动作 典型 API 模式
Stage 1: CopyIn MTE2 (搬运引擎) 从片外 GlobalTensor 切片搬入片内 LocalTensor (UB) DataCopy(inLocal, inGlobal, size)
Stage 2: Compute Vector (向量单元) 在片上 LocalTensor 之间就地执行高速数学计算 Add(outLocal, inLocal1, inLocal2, size)
Stage 3: CopyOut MTE3 (搬运引擎) 将计算完成的 LocalTensor 写回片外 GlobalTensor DataCopy(outGlobal, outLocal, size)

3. 后续课选读：优化前提

  • 对齐要求： 搬运接口常有地址和长度对齐要求（如 32 字节）；应按所用接口、数据类型与目标芯片核对。
  • 计算与搬运重叠： 双缓冲为不同数据块的搬运与计算提供并行空间，还需正确同步；收益受各阶段耗时与带宽等因素影响。把代码分成三个阶段并不自动保证重叠。
  • 定位瓶颈： 向量加法可能受访存带宽限制；具体瓶颈需要结合数据规模、实现方式与测量结果判断。
