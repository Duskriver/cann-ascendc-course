达芬奇 AI Core 硬件模型与流水线速查

算子执行视角下的昇腾片上存储层级与计算流水线拓扑。

🎯 算子开发第一法则： 昇腾 AI Core 的计算引擎（Vector / Cube）绝不直接访问片外 Global Memory。所有算子代码的本质，就是组织搬入 (CopyIn) ➔ 计算 (Compute) ➔ 搬出 (CopyOut) 三大阶段的高速吞吐。

2. Vector 算子三阶段流水线速查 (SPMD 范式)

典型三阶段流水硬件与核心动作对应关系
阶段 负责硬件单元 对应 Ascend C 核心动作 典型 API 模式
Stage 1: CopyIn MTE2 (搬运引擎) 从片外 GlobalTensor 切片搬入片内 LocalTensor (UB) DataCopy(inLocal, inGlobal, size)
Stage 2: Compute Vector (向量单元) 在片上 LocalTensor 之间就地执行高速数学计算 Add(outLocal, inLocal1, inLocal2, size)
Stage 3: CopyOut MTE3 (搬运引擎) 将计算完成的 LocalTensor 写回片外 GlobalTensor DataCopy(outGlobal, outLocal, size)

3. 算子调优黄金法则 (Storage Strength Checklist)

  • 带宽对齐规则： 昇腾 AI Core 数据搬运基本单元为 32 字节（32 Bytes Cache Line）。无论输入输出，地址与切分长度尽量保证 32 字节对齐。
  • 计算与搬运重叠： 纯串行执行效率低下，Ascend C 通过 双缓冲（Double Buffer） 技术让 MTE 搬运下一批数据的同时，Vector 单元正在计算当前批次数据。
  • 内存受限 vs 计算受限： 大多数 Vector 算子（如 Element-wise Add、Softmax）都是 Memory Bound（访存密集型），性能上限取决于 GM ↔ UB 的搬运效率。
