Lesson 0001 · 概念与心智模型

初识异构计算与达芬奇 AI Core

解密 NPU 核心算力：为什么 GPU/NPU 算子不能像 CPU 一样直接写指针？

🎯 直通实战目标 (Your Mission)： 我们最终要实现用 Ascend C 编写可在昇腾 NPU 上跑通且性能最优的自定义算子。要写出高效算子，第一步不是背诵 API，而是建立硬件数据流动的心智模型——数据在哪里、谁来计算、谁来搬运。

1. 异构计算的本质：Host（大脑）与 Device（超级工坊）

在传统的 CPU 编程中，计算与内存是平坦且统一的：CPU 直接读取主存中的数组，做完加法再写回主存。但在现代大模型与深度学习场景下，数据量动辄数十 GB，计算密度极高，通用 CPU 难以应对。

于是引入了异构计算（Heterogeneous Computing）架构：

  • Host（主机 CPU）： 负责整体业务逻辑控制、网络调度、以及向加速器发送算子下发指令（Kernel Launch）。
  • Device（昇腾 NPU）： 拥有超高并行度的计算加速卡，负责沉重的大规模张量与矩阵运算。
  • 连接总线： Host 与 Device 之间通过 PCIe 或高速总线（如 HCCS）相连。

2. 达芬奇 AI Core 内部：三大工种与存储分层

打开昇腾 NPU，其最核心的计算单元叫做 AI Core。不同于 CPU 的通用乱序执行，AI Core 内部高度专业化，明确划分了三类工种：

计算单元 对应现实类比 负责的算子类型与操作
Cube 单元 重型矩阵压铸机 大颗粒度矩阵乘法（$M \times K \times N$）。大模型注意力和全连接层的主力。
Vector 单元 高速向量流水线 一维张量元素级运算（加法、乘法、ReLU、GeLU、LayerNorm、Softmax）。
Scalar 单元 车间排产调度员 标量运算、循环控制计数、地址指针计算、分支跳转等逻辑控制。
⚠️ 核心认知铁律： 片外大容量显存（Global Memory / GM）容量大但访问速度慢；AI Core 内部的高速缓存（Unified Buffer / UB）速度极快但容量极小（只有几百 KB）。Vector 计算单元无法直接计算 GM 中的数据！

3. 算子流水线交互模拟器：CopyIn ➔ Compute ➔ CopyOut

在 Ascend C 算子中，所有 Vector 运算都必须遵循严密的三阶段流水线。点击下方按钮观察数据流的跃迁：

1. CopyIn 阶段
GM ➔ UB (MTE 引擎)
2. Compute 阶段
UB 内部运算 (Vector 单元)
3. CopyOut 阶段
UB ➔ GM (MTE 引擎)
阶段 1 (CopyIn)： MTE 搬运引擎启动，将待计算的张量切片从片外 Global Memory 异步搬运到片内高速 Unified Buffer (UB)。

4. 真机探针练习 (Hands-on Verification)

你手头有昇腾硬件环境。请在终端连接到昇腾机器，执行以下探针命令，查看你的昇腾 NPU 硬件配置：

# 查看昇腾芯片型号、驱动版本及温度功耗
npu-smi info

实操自检清单：

  1. 终端是否输出了类似 Ascend 910 或 Ascend 310 系列芯片？
  2. 输出界面中能否看到 HBM / 内存使用量（这就是我们在算子中说的 Global Memory）？
  3. 执行 echo $ASCEND_TOOLKIT_HOME，确认 CANN 软件栈开发套件的环境变量是否已配置。
