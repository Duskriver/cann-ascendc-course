一次加法的数据之旅：认识 CPU 与 NPU

跟着四对数字，弄清谁来算、数据放在哪，以及为什么要搬入、计算、再写回。

这节课结束时，你能做到：
  • 用自己的话说明 CPU 与 NPU 在本课中的分工。
  • 画出一次加法“搬入 → 计算 → 写回”的数据路线。
  • 在真实设备上找到 NPU 型号、设备编号和显存容量。

本课先建立一个够用的直觉。英文缩写可以随时查，不要求背诵；完整核函数留到下一课。

起点：适合接触过数组、函数和循环，但没有 GPU/NPU 编程经验的同学。若这些编程概念也不熟悉，先展开下面的准备说明。

课前准备：数组、函数、循环分别是什么？

数组是一排有顺序的数字，如 [10, 20, 30, 40]；函数把一组操作起个名字，方便重复调用；循环让某个动作按顺序做多次。

先练习把两排数字按位置相加，并用口头步骤说明怎么算。若需要学习基本语法，先补一个小练习：用熟悉的语言写出遍历数组并相加的函数，再进入后续代码课。本课可以先跟着数字和图学习。

在 AI 计算中，这样一个有明确输入、输出和计算规则的操作，叫作算子（Operator）。这个例子就是加法算子。后面把它交给 NPU 执行时，数学规则仍然一样；我们要学习的是怎样安排数据和计算。

四对数字只是为了方便观察。CPU 完全能完成这个小任务；这里不比较运行速度，也不意味着小任务交给 NPU 一定更快。

2. 谁来安排，谁来计算？ 10 分钟

CPU 是擅长通用任务的处理器，NPU 是面向神经网络等计算任务的加速器。让不同类型的处理器协同完成任务，叫作异构计算。本课采用下面这组分工：

主机 CPU · Host

像任务的组织者，准备输入、安排设备资源、发起计算，并在完成后处理结果。

昇腾 NPU · Device

像接到任务的计算车间。输入准备好以后，由设备上的计算单元执行加法。

两者之间需要软件协调。 是支持昇腾计算的软件栈；我们后面用 编写在设备上执行的计算程序，其中在设备上执行的核心函数叫核函数（Kernel）。这一课先认识它们的用途。

CPU 也支持并行与向量化；NPU 是否更快还取决于任务规模、数据传输等因素。不要把这组分工理解为 CPU 只能逐个数计算。

想一想：本课中，谁发起任务，谁执行加法？

3. 一次加法，数据怎样走？ 20 分钟

现在只看 NPU 内部。假设输入已经准备在设备的存储里：从主机把输入送到 NPU 的过程先不展开。下面的“大仓库”和“工作台”都属于 NPU。

🏢 大仓库：全局存储 GM（Global Memory）

放输入和最终输出，容量相对大。本例开始时，两排数字都在这里。

🛠️ 工作台：统一缓冲区 UB（Unified Buffer）

靠近计算单元，容量相对小。先把这次要计算的数据搬到这里，再进行向量加法。

你可以把设备上的计算核心 AI Core 想成一个车间。这里使用的向量计算单元 Vector像工作台旁的工人，负责按位置处理一组数字；搬运引擎 MTE负责在存储之间搬数据。先记住职责即可。

为什么需要工作台？靠近计算单元的存储便于快速取用数据，但容量有限。本课的向量加法接口使用 UB 中的数据，因此把要算的一小批先搬进去，用完再把结果写回大仓库。

  1. 搬入 · CopyIn：把 x、y 从 GM 搬到 UB。
  2. 计算 · Compute：在 UB 中做加法，新结果也先放在 UB。
  3. 写回 · CopyOut：把新结果从 UB 写回 GM 的输出位置。

这是本课采用的 Ascend C 向量加法模型。三步搬运和计算发生在 NPU 内部；“写回 GM”还不等于“把结果返回主机”。

先预测：完成“计算”，还没“写回”，新结果在哪里？

这是一张按功能简化的架构图，不是芯片的物理布局。不同产品的计算单元组合、存储容量和连接方式会有差别，开发时以具体型号文档为准。

📦 Global Memory (GM) —— NPU 的片外存储
在本课中： 我们从输入已经准备在 NPU 的 GM 中开始观察。GM 是容量较大的存储，具体容量和物理介质依设备型号而定。向量加法先将输入搬入 UB，再计算。
选读 C · 多块数据怎样重叠处理？

数据太多、工作台放不下时，可以分成小块逐批处理，这叫数据分块（Tiling）。同一块仍要先搬入、再计算、最后写回；不同块之间有机会重叠。

要让下一块搬入与当前块计算重叠，需要安排好不同数据块的缓冲空间和同步关系；双缓冲（Double Buffer）是常见方法。实现留到后续课。

读图假设：三块数据，每块的三个阶段均耗时 1 拍；缓冲与同步已就绪，各单元没有额外资源争用。“拍”是示意时间单位。现实各阶段耗时不同，收益需要实际测量。
